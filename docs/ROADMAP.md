# 项目开发路线图

> 本路线图按开题报告界定课程阶段的研究范围。待办项表示拟开展工作；只有代码和相应数值记录完成后才勾选，不把计划中的计算或 COMSOL 对照写成已有结果。

## 1. 项目目标与范围

使用 Python 有限差分法求解二维均匀介质、无自由电荷区域中的静电势，满足拉普拉斯方程

\[
\nabla^2 \varphi = 0, \qquad \mathbf{E} = -\nabla \varphi.
\]

课程阶段的主要成果是：可运行的二维求解程序、电势与电场图，以及能够说明计算可靠性的误差和敏感性记录。

### 研究算例

1. **矩形区域解析算例：** 在矩形区域上设置 Dirichlet 边界条件（上边界为 \(\varphi=f(x)\)，两侧与底边为零），用五点差分和 Jacobi 迭代求解，并与同一边界条件对应的解析解比较。
2. **有限宽平行板电容器：** 在正、负极板上分别设置 \(+V_0/2\) 和 \(-V_0/2\)，观察电势与边缘电场；改变极板宽度和板间距，比较边缘效应。

电容器算例开始前，需要明确计算区域、极板在网格上的表示方式及其余边界的处理方式，并在结果中记录这些设定。

### 课程阶段暂不纳入

- Neumann 或混合边界条件、Poisson 方程
- 非矩形网格区域、三维求解和 GPU 加速
- Gauss-Seidel、SOR 等其他迭代算法的性能比较
- 交互式可视化

这些方向可在课程主线完成后再评估，不作为当前阶段的完成条件。COMSOL 应用调研属于辅助工作；同模型数值对照仅在条件允许时开展。

## 5. 目标项目结构与 JSON 输入流

项目按“输入整理、算例构造、数值求解、结果分析与可视化”分层。以下是目标结构，按里程碑逐步建立；目录名和模块职责用于明确边界，不要求一次性创建所有文件。

M1 保留 `config.py → solver.py → main.py` 的轻量结构：`solver.py` 内完成矩形算例构造、解析对照与电场计算，尚未拆分 `cases.py`、`fields.py` 或 `visualize.py`。`scripts/validate_m1.py` 单独负责生成本地验收记录。

```text
.
├── configs/
│   ├── rectangle.json          # 矩形解析算例参数
│   └── parallel_plate.json    # 有限宽平行板算例参数
├── scripts/
│   └── format_input.py        # 接收并整理参数，校验后写出 JSON
├── src/electrostatic_bvp/
│   ├── config.py              # 读取并校验 JSON 配置
│   ├── cases.py               # 将算例参数转换为网格与边界条件
│   ├── solver.py              # Jacobi 求解并返回电势与收敛信息
│   ├── fields.py              # 根据电势计算电场和误差量
│   ├── visualize.py           # 绘制并保存电势、等势线和电场图
│   └── main.py                # 选择配置并串联完整计算流程
├── tests/                     # 求解器、算例构造与解析解验证
├── results/                   # 实际计算生成的图像和数值记录
├── docs/
├── README.md
├── pyproject.toml
└── uv.lock
```

### 输入与计算流程

1. `scripts/format_input.py` 接收用户填写的算例参数，调用与主程序共用的配置校验逻辑，并输出标准 JSON 文件。
2. `main.py` 读取指定 JSON；`config.py` 检查字段、类型与参数范围；`cases.py` 根据算例类型构造计算网格及 Dirichlet 边界数据。
3. `solver.py` 接收统一格式的网格和边界数据，以及 `tol`、`Nmax` 等求解参数，返回电势分布、是否收敛、迭代次数和最终变化量。
4. `fields.py` 从电势计算电场及验证所需的误差量；`visualize.py` 负责绘图和保存。

JSON 用于传递算例类型、几何参数、边界条件和求解设置等输入信息。网格数组、电势数组和电场数组由程序计算产生，不作为配置内容写入 JSON。输入脚本与主程序使用同一套校验规则，保证生成的配置可以直接复现计算。

测试应覆盖求解器的边界保持与收敛状态、算例构造结果，以及矩形算例相对解析解的误差。`results/` 仅保存实际运行得到的图像和数值记录，不把计划中的结果提前写入。
